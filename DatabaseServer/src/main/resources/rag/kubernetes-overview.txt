Kubernetes, abbreviated as K8s, functions as an open-source container orchestration system designed to automate software deployment, scaling, and management operations. Originally created by Google, the project is now sustained by a global community of contributors, with the Cloud Native Computing Foundation holding the trademark. The name derives from Ancient Greek, meaning "helmsman" or "pilot," and shares etymological roots with both "cybernetics" and "governor." The platform assembles multiple computers, whether virtual machines or bare metal, into a cluster capable of running containerized workloads, supporting various container runtimes like containerd and CRI-O.

Google announced Kubernetes on June 6, 2014, with the project conceived and created by Google employees Joe Beda, Brendan Burns, and Craig McLuckie, later joined by others including Ville Aikas, Dawn Chen, Brian Grant, Tim Hockin, and Daniel Smith. The platform's design drew inspiration from Google's Borg cluster manager and Promise Theory principles, with many primary contributors having previously worked on Borg. Unlike its predecessor Borg, which was written in C++, Kubernetes was developed in the Go programming language. Version 1.0 launched on July 21, 2015, after which Google collaborated with the Linux Foundation to establish the Cloud Native Computing Foundation, contributing Kubernetes as the foundational technology.

The Kubernetes control plane manages workloads and directs system communication, incorporating components such as TLS encryption, role-based access control, and robust authentication mechanisms. Etcd serves as a persistent, lightweight, distributed key-value data store that reliably maintains cluster configuration data, representing the cluster's overall state at any given moment. The API server exposes the Kubernetes API using JSON over HTTPS, processing and validating REST requests while updating API object states in etcd. The scheduler functions as an extensible component that selects appropriate nodes for unscheduled pods based on resource availability and constraints. Controllers operate as reconciliation loops that drive actual cluster state toward desired state through communication with the API server.

Nodes, also called workers or minions, are machines where containerized workloads are deployed, each requiring a container runtime and specific components for network configuration. Kubelet manages each node's running state, ensuring container health and directing pod lifecycle management as commanded by the control plane. Kube-proxy implements network proxy and load balancing functions, routing traffic to appropriate containers based on incoming request IP addresses and port numbers. Pods represent Kubernetes's basic deployable unit, consisting of one or more co-located containers on the same node, with each pod receiving a unique cluster IP address.

Kubernetes supports multiple workload abstractions beyond simple pods, enabling users to declaratively define and manage high-level constructs rather than individual pods. ReplicaSets maintain stable sets of replica pods, guaranteeing specified pod availability numbers, while Deployments provide higher-level management mechanisms for ReplicaSets handling updates, rollouts, and rollbacks. StatefulSets enforce uniqueness and ordering properties for pod instances, supporting stateful applications where state preservation is critical during restarts or scaling operations. DaemonSets ensure pod creation on every cluster node, proving particularly helpful for workloads with host dependencies like log collection and ingress controllers.

The Kubernetes API exposes an HTTP REST interface backed by etcd for persistent record storage, serving as the central communication mechanism for cluster components and external users. Custom Resources and Custom Resource Definitions enable API extension with non-standard Kubernetes object types without requiring cluster restarts. Kubernetes Operators combine custom resources and custom controllers, capturing human operator knowledge and automating service management, backup restoration, and application upgrades. The API implements comprehensive security strategies including transport-layer TLS encryption, multiple authentication mechanisms such as X.509 certificates and bearer tokens, and authorization modes including role-based access control.
